# 把销售前端数字员工门户交给另一个 Aily

发送 [sales-portal.zip](../aily/sales-portal.zip) 给目标 Aily，并附上下方的配置指令。ZIP 是可安装的 Aily 技能，不需要先克隆仓库或运行 Node.js。目标智能体的开发者可以在对话中上传 ZIP，或到开发后台的「技能」面板上传并启用。安装后用开发态配置持久化角色和能力，普通会话中的一次回复不会保存这些设置。[Aily 技能安装说明](https://aily.feishu.cn/hc/1u7kleqg_nto2bybm)

## 随附件发给目标 Aily

> 请安装附件中的 `sales-portal` 技能。在当前智能体的开发配置中，将名称设为「销售前端数字员工门户」，并将以下内容保存到人设指令。你是销售前端数字员工门户，收到「门户」「打开门户」「portal」、分类浏览、搜索、翻页、条目详情或能力推荐请求时，优先使用 `sales-portal`。初始设置 `PORTAL_MODE=demo`，欢迎语提示用户说「打开门户」。保存后在开发后台检查技能已启用，并在对话测试中依次发送「打开门户」「看 Skill」「下一页」「搜索 报价」。如果当前对话没有安装或编辑权限，请告诉我缺哪一步，我会到开发后台处理。请以实际保存和测试结果报告进度。

演示打开后应显示四类计数 **2 / 9 / 1 / 1**。翻到 Skill 第 2 页应只有「演示稿检查」。演示数据没有跳转链接。[完整验收用例](../aily/sales-portal/references/acceptance.md)

## 接入同一份正式目录

1. 在 Aily 开发后台启用飞书多维表格读取技能。为它的飞书执行身份申请 `base:record:read`，并给该身份目标表的读取权限。只按需要开启定位该表所需的读取权限。用对话测试确认能够读取「能力目录」表。[Aily 飞书技能与权限说明](https://aily.feishu.cn/hc/1u7kleqg_uv8vbhxz)
2. 在该智能体开发后台的人设指令中保存 `PORTAL_MODE=live` 与 `CATALOG_TABLE_URL=目标能力目录表的链接`。可选填 `PORTAL_CONTACT`，用于确实没有匹配能力时提供登记的联系方式。目录字段与卡片机器人一致，至少保留名称、类型和上架标记，跳转需要真实链接。若用种子数据建表，先把示例和占位链接换成经验证的真实入口，暂时拿不到时留空。[目录字段定义](superpowers/plans/2026-11-04-dept-agent-portal-phase1.md#task-2-目录数据模型与记录解析)
3. 用真实目录重跑验收，核对计数、搜索、详情、下架过滤和真实链接。测试通过后，再由目标智能体的开发者发布。如果希望企业内同事直接创建同款，可在发布前配置 Aily 的分享选项。[Aily 分享配置](https://aily.feishu.cn/hc/8dlnbe0s_ophgba65)

## 恢复原版群卡和个人卡

技能提供 Aily 对话里的完整目录导航。原版「群置顶大厅卡 → 点入口 → 个人卡私聊 → 卡内分类、搜索、翻页、Skill 展开」由仓库中的飞书机器人服务实现。两个入口可以读取同一份目录。卡片 JSON 可预览，真正的按钮回调由已运行的服务处理。

1. 按 [飞书测试应用配置](../README.md#接入飞书测试应用) 为原版卡片配置飞书应用、图片素材、多维表格和测试群。
2. 如果要在大厅卡上增加入口，开启新 Aily 的飞书渠道，把它的真实对话链接配置为机器人本地的 `ROUTER_LINK`，然后按 README 启动服务并重发大厅卡。
3. 在测试群验证置顶、点击后仅本人收到私聊卡，以及卡内按钮就地更新。使用两名测试用户核对各自的分类、搜索和翻页互不影响。真实数字员工入口需要在能力目录中分别登记目标 Aily 的 AppLink。

技能包未携带原应用凭证、真实表链接或旧应用的图片键。接手人只需在自己的目标环境内配置这些资源。

## 更新安装包

修改 [SKILL.md](../aily/sales-portal/SKILL.md) 或其引用后，在仓库根目录运行：

```sh
(cd aily/sales-portal && zip -X -FS ../sales-portal.zip SKILL.md references/*.md)
unzip -t aily/sales-portal.zip
```
