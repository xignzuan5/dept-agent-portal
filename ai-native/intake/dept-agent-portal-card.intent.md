# dept-agent-portal-card · 部门数字员工门户(飞书卡片)

**类型(type)**:architecture

> 背景:部门已有多个数字员工(aily 智能伙伴)、skill、知识库和团队服务,但散落各处,同事不知道「部门能做什么、该找谁」。需要一个以**飞书交互卡片**为载体的门户,集中展示并帮人路由。
> type 取 architecture:要新建自建飞书机器人服务(发卡/回调/卡片实体更新/统计)+ 多维表格目录 + aily 路由 agent,属新 infra;偏大往上取。
> 来源:2026-11-04 提需求商量。卡片能力上限与限制已查证官方文档(见文末「已查证约束」)。

## 目标(owner 下达)
做一个**部门数字员工门户**,以飞书交互卡片呈现,集中展示部门的 **agent(数字员工)、skill、知识库、团队对外服务**;用户点 agent 直接跳到对应 aily 智能伙伴对话,点 skill 就地看详情;并有一个**路由 agent**,读懂用户需求后推荐最合适的条目(说明理由 + 跳转按钮),让用户知道部门能提供什么服务。
**卡片要用足飞书卡片 2.0 的交互能力,不能做成简陋的文字列表。**

## 范围(in)
- **能力目录(唯一数据源)**:一张多维表格,登记 agent / skill / 知识库 / 团队服务;字段至少含:类型、名称、一句话简介、详细说明/用法、标签、负责人、跳转链接(aily 对话 / 知识库 / 文档)、图标或头像、排序、上下架。门户卡片与路由 agent 都只读这张表。
- **群大厅卡(群置顶)**:部门名 + 副标题 + 能力数标签(如「12 个 agent · 30 个 skill」);一句话部门介绍;能力数概览(agent / skill / 知识库 / 服务 四个指标块);热门 agent 磁贴 3–4 个;主按钮「打开门户」+ 次按钮「问路由助手」。群内所有人看到的是同一张,**不承载个人化交互**。
- **个人版门户卡(仅本人可见)**:点「打开门户」后给本人发一张仅自己可见的完整门户卡(优先群内「仅特定人可见」临时卡片,不支持则发到机器人私聊)。包含:
  - 顶部**输入框直接问路由**(「我想做 X,该找谁」);
  - **分类切换**(agent / skill / 知识库 / 团队服务)按钮组,回调 3 秒内返回新卡片就地切换;
  - **搜索框 + 标签筛选下拉**;
  - 条目以**可整块点击的磁贴网格**展示(头像/图标、名称、一句话简介、彩色标签、负责人头像);
  - agent 磁贴:点击**跳转对应 aily 对话,同时回调记一次点击**(跳转与回调共存,不经中转页);
  - skill:**折叠面板就地展开详情**(简介、用法、示例、负责人);
  - 知识库:打开对应知识库链接;
  - 条目多时**翻页**(上一页/下一页 + 页码);
  - 每个条目标注**负责人,可一键联系**。
- **路由 agent(用 aily 搭)**:以多维表格目录为知识;回答形式为卡片:推荐 1–3 个条目,每条附理由 + 跳转按钮;问到部门不提供的服务时**明确说没有并给出联系人,不硬推荐**。两个入口都要:① 个人版门户卡里直接问,答案在卡片里**流式逐字出现**(自建机器人转调 aily);② 「问路由助手」按钮跳到 aily 对话里继续聊。
- **随时调出门户**:机器人自定义菜单 + 指令(如发「门户」)随时调出个人版门户卡。
- **卡片跟着表自动更新**:多维表格记录增删改后,大厅卡与新打开的个人版门户卡 **1 分钟内**体现(事件驱动,不靠长轮询)。
- **大厅卡长期有效**:卡片发出 14 天后点击引起的更新会失效,需在到期前**自动重发并重新置顶**。
- **使用统计**:记录谁点了哪个条目、路由推荐了什么、是否命中;数据落多维表格;提供一张管理员可看的统计卡片(含图表:热门 agent/skill 排行、路由命中情况)。
- **视觉**:卡片 2.0;配亮/暗色颜色 token;PC 与移动端都正常;过 lark-im 卡片「好看的标准 P0–P7」自检。

## 范围(out)
- 路由**只推荐 + 给跳转,不代为转交处理**(用户自己点过去和对应 agent 聊)。
- 目录**不自动从 aily / skill 仓库等处收集**,以多维表格人工登记为准。
- 群大厅卡上**不做**分类切换 / 搜索 / 翻页(避免共享卡片一人操作、全员跟着变)。
- <待补>:商量时未勾选任何明确不做项。是否做网页版门户、是否按人区分权限、是否只服务本部门(不做成多部门通用模板),需 owner 补充确认;默认按「不做网页版、不分权限、只服务本部门」理解。

## 验收(4 档)
1. **artifact**:自建飞书机器人应用(发卡 / 回调 / 卡片更新 / 统计服务)+ 多维表格能力目录(含上述字段)+ 群大厅卡 + 个人版门户卡 + 路由回答卡 + 统计卡(均为卡片 2.0 JSON 或卡片模板)+ 路由 aily agent。
2. **可证**(在测试群可复现):
   - 发出大厅卡并置顶 → 点「打开门户」收到仅自己可见的门户卡 → 点任意一个 agent 都能打开对应 aily 对话;skill 能就地展开详情;知识库链接都能打开。
   - 在多维表格新增或修改一条 → **1 分钟内**体现在大厅卡和新打开的门户卡上。
   - 准备一组 **20 个**典型问题问路由 agent → 推荐正确率 **≥ 90%**(问题集与判定标准先登记到多维表格,便于复跑)。
   - 问一个部门不提供的服务 → 路由明确说明没有并给出联系人,不硬推荐。
   - 统计表里能看到上述操作产生的点击与路由记录。
3. **按需档**:卡片过 P0–P7 自检;PC / 移动端 / 深色模式截图可读;单卡 ≤ 200 个组件、≤ 30KB;回调 3 秒内响应(超时会让用户看到请求错误)。
4. **不回退**:大厅卡超过 14 天仍能正常点击和更新(到期前自动重发重置顶);同一时间多人在群里打开个人版门户互不影响;已有 aily agent 的原有对话行为不受影响。

## 已查证约束(2026-11-04,飞书开放平台文档)
- **卡片 2.0 只有共享模式**(`update_multi` 只能为 true):卡片被更新后,所有收到这张卡的人看到的都会变 → 个人化交互必须放在「仅特定人可见」临时卡片或私聊里。
- **单卡 ≤ 200 个组件、≤ 30KB**;客户端版本低于 7.20 只显示标题。
- **回调 3 秒内响应**,可以直接返回新卡片(raw JSON 或模板)+ toast 提示;延时更新的 token 30 分钟内有效,最多用 2 次。
- **卡片发出 14 天后,点击引起的更新不再生效**(回调本身 30 天内有效);**卡片实体有效期 14 天**,用卡片实体更新的频率上限为 50 次/秒。
- 卡片实体支持按 `element_id` **局部更新组件**、**流式更新文本**(打字机效果,需开启 `streaming_mode`)。
- 「仅特定人可见」卡片:`/open-apis/ephemeral/v1/send`,不支持话题群,同一个群最多 40 次/秒。
- aily 的工作流有「发送飞书卡片」节点(使用卡片搭建工具里的模板),支持按钮回调。

## 待验证(首个切片先做技术验证)
- 「仅特定人可见」临时卡片是否完整支持卡片 2.0 的组件和交互 → 不支持则个人版门户改发到机器人私聊。
- aily 路由 agent 能否回带跳转按钮的卡片 → 不行则**路由放进自建机器人**(owner 已定兜底)。
- 自建机器人能否调用 aily 接口拿到路由回答,并流式写进卡片(卡片内直接问)→ 不行则同上,改由自建机器人做路由。
- 多维表格记录变更事件能否在 1 分钟内触达服务(支撑「改表 1 分钟内生效」)。
